# Harness 设计说明

## 模块边界

四个产品功能独立配置、独立触发、独立产物目录；不会把科研和短视频任务串成一个 workflow。它们可以共用一个本地 MLX 推理进程、同一套专家角色机制和基础日志，但不互相传递未请求的数据。

| 模块 | 入口 | 当前状态 | 后续工具 |
| --- | --- | --- | --- |
| 日常对话 | CLI、Slack 私聊/@提及 | 本地模型对话、白名单、SQLite 对话记录；Slack 文件回传命令 | 文件检索分析、定时提醒 |
| 科研 | `xue-harness run research` | 研究助理 + 学术审校两阶段草稿 | Zotero、PDF、DOI/引用核验、期刊新闻 |
| 短视频 | `xue-harness run video` | 原创脚本 + 发布检查草稿 | SVC、固定形象动画、字幕/剪辑、按任务云 GPU |
| 热点捕获 | 独立计划任务/Slack 摘要（待接） | 来源和管线定义 | 正能量/学术新闻、二次元趋势、授权下载/转写 |

借鉴 Ruflo 的任务路由、专家协作、共享记忆和结果检查闭环，但不复制其大型 swarm/MCP 表面。每个功能只运行自己的小型 DAG；记忆存事实和用户决策，不把全部原始对话无限放进模型上下文。

Agency Agents 中文版更适合当作专家岗位目录和工作方法参考；按任务挑选角色，而不是让 200 多个角色同时运行。其上游角色定义有 MIT 授权标注；实际集成时保留许可证/来源并固定上游版本。

Agency Agents 中文版更适合当作专家岗位目录和工作方法参考；挑选科研、短视频策划、运营和审校角色，按任务拼装，而不是让 200 多个角色同时运行。其角色定义有 MIT 授权标注；集成时保留许可证/来源并固定上游版本。

## 运行结构

```text
iPhone Slack ── Socket Mode ── 日常对话 + 明确命令的文件回传
                                    │
CLI ── 日常对话                         ├── SQLite 对话记忆/运行记录
CLI ── 科研模块 ── Zotero/PDF/引用工具（独立）
CLI ── 短视频模块 ── 脚本/SVC/数字人/剪辑（独立）
定时器 ─ 热点模块 ─ RSS/公开来源/Slack 摘要（独立）
                                    │
                           共用本机模型客户端
                                    │ 127.0.0.1:8080
                                    ▼
                               mlx-lm
```

高算力任务只有在云策略准许时才进入短时 Serverless GPU 或临时 Pod；任务完成后将产物同步回 Mac 并自动终止云端 worker。

Slack 当前只开放日常对话和用户明确调用的文件回传命令。科研、视频和热点模块未来各接自己的入口与工具。确定性工作交给普通程序：PDF/网页抽取、去重、字幕时间戳、素材校验、压缩和渲染；LLM 负责分类、摘要、草稿与审校。准确性来自来源、结构化产物和复核门。

## 专家角色

| 角色 | 主要产物 | 适合模型 |
| --- | --- | --- |
| 日常助理 | 直接答复、文件分析计划 | 本地模型；敏感数据默认本地 |
| 科研助理 | 问题拆解、文献矩阵、摘要草稿 | 本地模型 + 联网来源/引用核验 |
| 学术审校 | 引用/方法/因果表达问题清单 | 对关键结论由 Codex 或人工复核 |
| 短视频策划 | 选题角度、分镜、口播稿、字幕节奏 | 本地模型 + 人工品牌审查 |
| 内容安全审校 | 事实、版权、平台规范、敏感点清单 | 规则检查 + 人工终审 |

在 36 GB 统一内存机器上，不建议给每个角色各加载模型。所有角色调用相同模型服务，按工作流顺序执行；无模型的工具阶段可并行。

## 服务拆分与边界

- **本地模型进程**：MLX-LM 只绑定回环地址。首选 Qwen3-14B 4-bit（模型卡标示权重约 8.31 GB），如果实际响应延迟高，再比较 Qwen3-8B 4-bit。M4 Max/36 GB 是本机报告的硬件值，内存仍要留给 macOS、浏览器、剪辑软件和 KV cache。
- **云端 GPU**：任务标记为 `local`、`cloud-batch` 或 `user-approval`。日常文本任务留在本机；图像/视频生成等任务可进入云队列。执行前先估价并预留额度，达到单任务/月度上限就拒绝启动；设置硬超时，回传结果后终止 worker 和非必要存储。按秒计费且可缩到零的 Serverless 优先；不支持的工作负载再用临时 Pod。
- **编排**：本地 Python CLI 起步，后续 Slack 事件进入持久任务队列；失败步骤可重试，不重复执行有副作用的工具调用。
- **记忆**：SQLite 保存任务状态、来源、用户决策和产物索引。科研引用仍保留 DOI/URL/页码；向量检索可后加，先避免增加常驻依赖。
- **权限**：文件回传只限 `config/file_roots.yaml` 配置的目录和白名单 Slack 用户；只响应明确的“发送/打包”命令。写 Zotero、移动/删除文件、收藏或发布操作仍需要具体确认。工具日志记录操作者、参数摘要、结果路径。
- **远程**：推荐 Slack Socket Mode 或 Tailscale，不把本地模型 HTTP 端点暴露在公网。文件传输仅从显式共享目录下载，并设置大小上限。

## 服务选型与可替换项

- **Zotero/知网/期刊**：Zotero 的 MCP 项目不是官方组织发布时，必须按社区软件评估和固定版本；也可先走 Zotero Connector 导入、Better BibTeX 导出/本地文件读写。知网和期刊资料从你有权限访问的页面、RIS/BibTeX 导出或官方 API 进入；不通过绕过付费墙或访问限制来抓取。不要将“有 MCP”误认为官方或稳定 API。
- **抖音趋势**：建议公开榜单/RSS/官方能力或用户手动提交链接，再将链接下载、转写和内容特征分析；默认不开启自动收藏/自动点赞/自动关注。MediaCrawler README 禁止商业用途，因此不纳入可营收的生产工作流。Douyin_TikTok_Download_API 是非官方自部署 API，部署不等于获得平台授权，需在决定采集方式前单独核查平台规则。
- **视频剪辑**：复用 ArcReel 的阶段式素材、分镜、可重做和剪映草稿导出思想；CapCut 与剪映草稿兼容性不能假设等同。首个可控版本用静态角色立绘/PNG 序列、配音 WAV、字幕 SRT 与 FFmpeg 合成，随后再评估 Live2D/剪映草稿。
- **声音转换**：SVC 模型、训练材料和输出声音需要你拥有或获许可的录音素材；先做本地离线转写/音频分离/转换原型，默认不上传原声。
- **新闻推送**：学术 RSS/期刊/预印本官方 API 可按主题和日期拉取，LLM 做摘要并附原始链接；先采用每天定时摘要，重要新闻通知可由用户设关键词。

## 成本与升级阈值

| 项目 | MVP | 何时花钱 |
| --- | --- | --- |
| 文本模型 | 本地 MLX | Mac 并发明显不足且任务量证明云 GPU 更省时 |
| Codex | 交互式深度任务/代码审查 | 仅使用已有订阅；不作为服务端 token API |
| Slack | 现有工作区 Bot | 需要企业权限/付费保留/高级合规功能时 |
| 云 GPU | 有高算力任务时突发 | Serverless 当前公开起价 $0.58/h、按秒计费并可缩到零；$10/月覆盖数小时，具体看卡型与任务 |
| 外部生成 API | 暂不接 | 先用本地方案，确保所有订阅 + API 总额 ≤ ¥68/月 |

服务器适合临时高强度算力，不适合作为这笔预算下的 24/7 家庭常驻推理端；实际价格随供给、区域、磁盘和流量变化。许多 GPU 规格是固定时价，低价“时段”不一定存在；省钱重点是按秒/按任务计费、选择合适的显存档位，以及不让实例空转。停止 Pod 后磁盘仍可能继续收费，临时批处理结束时要终止不需要的资源。

## 分阶段交付

1. **MVP**：CLI + 单本地模型 + 角色 YAML + 本地记录。
2. **收入实验优先**：热点摘要 → 人工选题 → 原创脚本 → 固定动漫形象/本地音频 → 字幕/剪辑草稿；测每条视频的时长和成本，只有特定高算力步骤排入云 GPU。
3. **研究**：Zotero 只读与 PDF 摘要，引用核验必须带 URL/DOI/页码，未知就标未知。
4. **手机常驻**：Slack Socket Mode、任务队列、文件白名单、`launchd`、备份与恢复。
5. **自动趋势捕获**：仅在合规来源、速率与保存范围明确后接入；所有平台账号副作用仍确认后执行。
